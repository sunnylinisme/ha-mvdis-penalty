# 使用說明

這個 Add-on 會定時查詢監理服務網、在 Home Assistant 主機本機辨識驗證碼、建立實體，並在出現新罰單時建立永久通知。最多可設定 5 位本人或已授權管理的查詢人。

> 本專案並非交通部、公路局或監理服務網的官方服務。重要資料請回到監理服務網確認。

## 設定

請只設定本人，或你已獲合法授權管理的身分資料。

- **主要查詢人名稱**：顯示在實體與通知中的名稱，例如「本人」。
- **身分證字號**：主要查詢人的台灣身分證字號，例如 `A123456789`；會檢查格式與檢查碼。
- **出生年月日（民國）**：固定七碼。例如民國 78 年 7 月 2 日填 `0780702`。
- **其他查詢人**：可再加入最多 4 人；每人都要填名稱、身分證字號及七碼民國出生年月日。
- **查詢間隔（小時）**：每次查詢之間的間隔，預設 24，最小值 6。
- **驗證碼最多嘗試次數**：每位查詢人正式提交查詢表單的上限，預設 1。每輪會在同一個網站 Session 內自動查看最多 5 張驗證碼；低信心圖片只換圖、不提交身分資料。只有監理站仍常拒絕高信心答案時才建議提高。

設定後按下「儲存」，Add-on 會在約 5 秒內自動檢查格式、檢查碼與日期，接著立即向監理服務網驗證並查詢，不必重新啟動或等待下次排程。Home Assistant 的設定儲存畫面本身無法連線監理服務網，因此完整結果會顯示在「開啟網頁介面」中；錯誤會標明是哪位查詢人及需要修正的欄位。也可到「日誌」確認出現 `MVDIS query succeeded`。網頁介面另提供立即查詢與測試通知。安裝與更新會直接下載 GitHub 預先建置的映像檔，不會在 Home Assistant 主機上編譯或安裝 OCR 套件。

## 查詢與通知規則

每人的第一次成功查詢只會建立獨立基準，不會把原本已存在的紀錄誤報為新罰單。同一天的不同違規會以日期、事實、地點及可用單號等欄位分別識別，不會互相覆蓋。單一查詢人的驗證碼或身分資料失敗不會中止其他人的查詢；多人查詢之間會保留短暫間隔，避免短時間請求尖峰。之後若發現從未回報過的紀錄，Add-on 會：

1. 建立 Home Assistant 永久通知。
2. 觸發 `mvdis_penalty_new_case` 事件，供手機推播或其他自動化使用。
3. 更新相關感測器。

Add-on 不會勾選任何紀錄，也不會啟動繳費程序。

若發生連線逾時、網路中斷或監理服務網錯誤，Add-on 會停止本輪其餘查詢並進入 30 分鐘冷卻，之後自動重試；期間保留上次成功結果，也不允許重複按鈕查詢。驗證碼選擇失敗不會觸發全域冷卻，只會讓該查詢人在 15 分鐘後自動補查；其他查詢人不受影響。

已通知過的紀錄識別碼會保留在本機狀態中，因此同一筆紀錄暫時消失後重新出現時，不會再次通知。

## 內建查詢頁面

網頁介面由 Home Assistant Ingress 保護，不對區域網路開放連接埠。頁面會顯示最近更新、下次排程更新及可再次立即查詢時間、監理服務網回傳的完整罰單表格欄位，並提供立即查詢與測試通知。相同設定查詢後 5 分鐘內不會因重新啟動或連續按鈕而再次連線；手動查詢完成後會重新計算下一次排程。測試通知不會建立罰單資料。設定格式錯誤時，頁面會顯示查詢人名稱、原因與修正方式；設定可送出查詢但身分資料遭監理服務網拒絕時，則會在該查詢人的卡片中顯示失敗。其他查詢錯誤會區分驗證碼、網站格式、逾時及網路等類型。

若先前有未繳紀錄而本次結果已清空，Add-on 會建立確認提醒並觸發 `mvdis_penalty_cleared`。這只能代表紀錄已不在查詢結果中，仍應回監理服務網確認。從設定移除查詢人後，其舊實體及群組會在下次查詢時清理。

## 建立的實體

- `sensor.mvdis_penalty_unpaid_count`：未繳筆數
- `sensor.mvdis_penalty_total_amount`：未繳總金額
- `binary_sensor.mvdis_penalty_has_unpaid`：是否有未繳罰單
- `sensor.mvdis_penalty_last_check`：最後查詢時間
- `sensor.mvdis_penalty_status`：最後查詢狀態

這 5 個固定 ID 屬於主要查詢人，因此升級不會破壞既有儀表板或自動化。其他查詢人會各有同樣 5 個實體；ID 會加入不含身分證字號的識別碼，介面名稱則會顯示查詢人名稱。

每位查詢人另有一個可搜尋的群組實體，主要查詢人為 `group.mvdis_penalty`，其他查詢人的群組 ID 會包含相同的本機識別碼。點開群組即可集中查看該人的 5 個實體。由 Add-on 直接建立的實體在「裝置與服務」頁仍可能列於「未分組」，這是 Home Assistant REST 狀態實體的限制，不影響群組、查詢或通知。

## 手機推播（選用）

將下列自動化中的 `notify.mobile_app_your_phone` 改成自己的手機通知動作：

```yaml
alias: 監理站發現新罰單
triggers:
  - trigger: event
    event_type: mvdis_penalty_new_case
actions:
  - action: notify.mobile_app_your_phone
    data:
      title: "監理服務發現新罰單"
      message: >-
        {{ trigger.event.data.profile }}新增 {{ trigger.event.data.count }} 筆：
        {{ trigger.event.data.summaries | join('；') }}
mode: queued
```

## 常見問題

### 驗證碼持續失敗

Add-on 會在同一個網站 Session 內查看最多 5 張驗證碼。每張圖都會進行多種本機辨識，只有結果一致且信心達標才會正式提交；低信心圖片只執行網站原生的「換一張」，不會送出身分資料。5 張都未達門檻時，該查詢人會在 15 分鐘後自動補查。預設仍只允許一次正式提交；只有監理站經常拒絕高信心答案時才建議提高「驗證碼最多嘗試次數」。

### 沒有通知

第一次成功查詢只會建立基準。請先確認五個實體已建立，並在日誌找到 `MVDIS query succeeded`。後續新增且未見過的紀錄才會通知。

### 資料尚未出現

監理服務網的違規資料必須等舉發機關登錄後才會顯示，可能不是即時更新。本 Add-on 只能呈現網站當下回傳的資料。

## 隱私與安全

- Add-on 設定由 Home Assistant Supervisor 保存，並非靜態加密；請妥善保護管理員帳號與備份。
- 身分證字號及出生年月日不會寫入日誌或實體狀態；額外實體 ID 使用本機隨機金鑰產生的識別碼。
- 查詢到的罰單欄位會保存在 Add-on 資料及 Home Assistant 實體屬性中，以供頁面、通知與自動化使用；請妥善保護 Home Assistant 資料庫及備份。
- 驗證碼使用精簡自 `ddddocr` 的辨識模型與 `onnxruntime` 在本機處理。
- 不會對區域網路開放任何連接埠。
- 建議保留至少 6 小時的查詢間隔，避免對政府網站造成負擔。
